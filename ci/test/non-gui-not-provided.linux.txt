# Integration tests (db-backend and backend-manager) the Linux `test-non-gui`
# lane does NOT provide the tools for.
#
# That lane runs `just test-rust` with CODETRACER_ALLOW_GRACEFUL_TEST_SKIPPING=false,
# so a test whose prerequisite is missing FAILS there instead of passing having
# asserted nothing. The tests below need tools the lane does not install; they
# are excluded by name from both crates' nextest runs, and `just test-rust`
# prints every line of this file that applies to a crate as NOT RUN, with the
# lane that does run it.
#
# A new test that needs a tool this lane lacks fails the lane until it is added
# here or the lane provisions the tool. That is intended: the decision is made
# once, in review, instead of the test quietly skipping forever.
#
# Format: <nextest filterset> | <prerequisite the lane lacks> | <lane that runs it>
#
# The filterset is `binary(<target>)`, or `binary(<target>) and
# test(/<regex>/)` for a binary only some of whose tests need the tool. The
# target is an integration test of exactly one crate,
# src/db-backend/tests/<target>.rs or src/backend-manager/tests/<target>.rs:
# ci/lib/not-provided-filter.sh hands each crate's nextest run only that
# crate's entries, because nextest refuses a `binary()` that names none of its
# binaries. A regex is anchored and kept to the syntax POSIX ERE and Rust's
# regex crate read alike (it may contain `|`; the field separators are the
# line's last two), so ci/test/lane-not-provided-test.sh can evaluate it.
#
# The lane is the id of the job that runs the test, optionally followed by a
# parenthesised note. ci/test/lane-not-provided-test.sh checks that every
# target exists in one crate, every regex matches a test there, and every lane
# names a job in .github/workflows/; there is no "runs nowhere" entry. A
# backend-manager entry's lane selects its tests from this same line
# (`ci/lib/not-provided-filter.sh --lane <job>`), so the lane that excludes a
# test and the lane that runs it cannot disagree about which tests those are.
