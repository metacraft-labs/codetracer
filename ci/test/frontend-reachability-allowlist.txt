# frontend-reachability-allowlist.txt
#
# Exported frontend symbols that legitimately have no cross-module product
# reader. Read by `ci/test/frontend-reachability-guard.py`.
#
# FORMAT
#     <symbol>  # <reason>
#
# The reason is MANDATORY and is checked: an entry without one, or with one
# shorter than twelve characters, fails the guard outright — not as part of the
# backlog, but as a defect in this file. That check exists because an
# allow-list which grows without review becomes the thing it was meant to
# prevent. "known issue", "ok" and "see ticket" are not reasons; write what
# reaches the symbol instead, and why that reach is invisible to a name scan.
#
# Entries naming a symbol that is no longer declared anywhere are also
# reported, so this file cannot quietly become a record of deleted code.
#
# WHEN AN ENTRY IS CORRECT
#     * The symbol is reached by something that is not a Nim name: an IPC
#       message handler resolved by string, a `{.exportc.}` boundary, a
#       dispatch table built at runtime, an IsoNim view mounted by id.
#     * The symbol is a published API this repository is not the only consumer
#       of — the Embed SDK surface, an extension entry point.
#     * The symbol is one arm of a deliberately total interface (every case of
#       an enum, every accessor of a facade) where the unused arms exist so the
#       interface cannot drift.
#
# WHEN AN ENTRY IS WRONG
#     * "It will be used soon." Then it is not reached today, and the pane it
#       belongs to looks present and does nothing. Delete it or wire it.
#     * "The test covers it." That is the defect, not the exemption. A tested
#       capability nothing reaches is exactly what this guard is for.
#
# The list started empty on purpose. The first run reported 1180 findings
# across buckets A and B; adding entries before those are triaged would be
# recording the backlog rather than clearing it.
#
# THE FIRST ENTRIES, 2026-10-22: three IPC handlers that landed after the
# ceiling was last set (2fc6c5764) and are reached by string. Older handlers of
# the same shape are still counted in the backlog; they are not listed here
# because triaging them is a pass of its own, not a side effect of this one.
#
# HOW AN `on<Name>` IPC HANDLER IS REACHED. `configureIpcMain` in
# `src/frontend/index/ipc_utils.nim` lists message names as string literals
# inside `indexIpcHandlers("CODETRACER::")`. That macro
# (`src/frontend/index/base_handlers.nim`) builds the handler's identifier with
# `("on-" & message).toCamelCase` and registers it with
# `ipc.on("CODETRACER::" & message, handler)`. So `"keybindings-import"` reaches
# `onKeybindingsImport` at compile time, and no source line ever spells the
# handler's name. An entry is correct only while its message string is in that
# list: delete the entry together with the string.
