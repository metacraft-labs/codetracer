# db-backend integration tests the Windows `windows-rust-components` lane does
# NOT provide the tools for.
#
# That lane runs ci/test/windows-rust-components-tests.sh with
# CODETRACER_ALLOW_GRACEFUL_TEST_SKIPPING=false, so a test whose prerequisite is
# missing there FAILS; the tests below are excluded by name and printed as NOT
# RUN with the lane that runs them.
#
# What the lane provides: env.ps1's toolchain (Rust/MSVC, nim/nimble, capnp,
# node/npx, nargo, go, gcc/clang, TTD + WinDbg), the db-backend siblings
# (codetracer-trace-format(-nim), codetracer-native-recorder), and
# `ct-native-replay`, built from the codetracer-native-backend sibling. So the
# Windows recorder tests -- TTD, the recorder Language-Support-Matrix.md lists
# for Windows -- run here: dap_ttd_windows_smoke and the Go / Nim / Rust TTD
# flow tests. So do the Noir tests (env.ps1 builds nargo).
#
# What it does not, and why:
#
#   - The interpreted-language recorders (Python, Ruby, JavaScript, BEAM, PHP,
#     the shell recorders), WebAssembly (wazero) and the blockchain recorders
#     are not supported on Windows (Language-Support-Matrix.md lists Python,
#     Ruby and JavaScript as "--" there). Their tests run on Linux. The one
#     exception is the materialized Python value-origin suite, which
#     origin-dap-windows runs on Windows with the locked Python recorder.
#   - MCR flows need `ct-mcr`, which only windows-headless-test builds on
#     Windows, and replay through ct-native-replay; they run in mcr-dap-flow.
#   - Lean has no Windows toolchain path (Language-Support-Matrix.md); its flow
#     test runs under rr.
#   - The cross-process recordings are produced by
#     scripts/materialize-recording.sh with `ct-instrument`; `ct-print` is a
#     codetracer-trace-format-nim build product. Neither is built here.
#   - `black` (the Python autoformat test) is not in env.ps1.
#
# Format and checks: as in non-gui-not-provided.linux.txt
# (ci/test/lane-not-provided-test.sh).
