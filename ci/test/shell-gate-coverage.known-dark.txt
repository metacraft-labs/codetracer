# Gates that no CI lane can reach, with why each is still here.

# THIS FILE FAILS IN BOTH DIRECTIONS. A listed gate that stays dark is reported
# and does not fail the run. A listed gate that BECOMES REACHABLE fails the run,
# by name, demanding its line be deleted — so an entry cannot outlive the hole
# it records, and nobody has to remember to clean up after wiring one.
#
# AND IT CAN NO LONGER GROW QUIETLY. The directive below is the list's own
# length, and `shell-gate-coverage.sh` fails unless the number of entries EQUALS
# it. Not `<=`: slack under a ceiling is a budget for new dark gates, and the
# cheapest way to make this guard green has always been to append a line.
# Recording a new hole now means editing this number upward in the same diff,
# where a reviewer sees it; wiring one up means editing it downward, which the
# both-directions rule already forces in the same commit.
#
# RECORDED-DARK-CEILING: 25
#
# It is not an exemption list. `NOT-A-CI-GATE:` in a file's own header is the
# exemption, and it means "this is not a gate" — a claim about the file, made in
# the file, that a reviewer can disagree with. Nine scripts under `scripts/` say
# that about themselves: developer setup, a PATH diagnostic, a stylus generator
# and six documentation-capture tools. This file means the opposite: these ARE
# gates, they SHOULD run, and today nothing runs them. (One entry — the
# `ci/lib/` library at the bottom — is neither, and says so on its own line.)
#
# ENTRIES ARE REPO-RELATIVE PATHS, NOT BASENAMES, since 2026-09-04: the guard's
# scan was widened from `ci/test/ -maxdepth 1` to every `*.sh` under `ci/` and
# `scripts/`, and that made basenames ambiguous — `nix.sh` is both
# `ci/build/nix.sh` and `ci/lint/nix.sh`.

# ---------------------------------------------------------------------------
# WHAT THE 2026-09-04 REMEASUREMENT CHANGED, AND WHY THE LIST GREW BY FOURTEEN
# ---------------------------------------------------------------------------
# The previous count — 96 found, 88 reachable, 8 recorded dark, 0 UNRECORDED —
# was green, and the green was the finding. Two things made it a fiction:
#
#   * THE JUSTFILE WAS A CI ROOT. Every gate named by any of 208 `just` recipes
#     counted as reached, whether or not a lane calls that recipe. `just` is a
#     developer entry point; 57 of its recipes are reachable from a workflow and
#     151 are not. Thirteen gates were credited to recipes in the second group.
#   * THE SCAN WAS ONE DIRECTORY. `ci/verdict/`, `ci/runner/`, `ci/lib/`,
#     `ci/build/`, `ci/deploy/`, `ci/reprobuild/` and all of `scripts/` were
#     outside the universe of the check whose job is to find dark gates.
#
# Honest figures, same tree, same day: 161 found, 130 reachable, 9 declared
# not-a-gate, 22 recorded dark, 0 UNRECORDED.
#
# TWO ENTRIES EVICTED THEMSELVES, which is the both-directions rule working
# rather than a decision anyone made. `cross-process-gate.sh` and
# `origin-dap-gate.sh` are reached by `just test-cross-process` and
# `just test-origin-dap`, both called directly by `codetracer.yml`. The old
# scan could not see it because it stopped at basenames in the justfile.
#
# AND ONE CLAIM WAS REFUTED. An audit listed `sibling-backend-path-test.sh`
# among the gates running in no lane. It is not: `codetracer.yml` runs
# `ci/test/non-gui.sh`, which runs `just test`, which depends on
# `test-sibling-backend-path`, which runs it. Four hops through two kinds of
# node — which is the whole reason reachability is walked and not grepped.
#
# Wiring these is deliberately NOT done here. Each needs an owner who knows what
# it costs to run, what it needs on the runner, and whether it passes today — and
# a guard author quietly adding twenty-two unknown jobs to CI would be making
# twenty-two decisions that are not theirs. What is done here is making the number
# impossible to lose.
#
